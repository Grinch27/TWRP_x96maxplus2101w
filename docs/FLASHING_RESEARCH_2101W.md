# X96 MAX+ 2101W (4 GiB / 64 GiB) — Flashing Research and Recovery Gates

> This document is **research and an offline safety checklist, not authorization to flash**. The TWRP 9.0 Native workflow does **not** connect to or modify a device. No TWRP image is known to boot on a 2101W yet.

## Device identity and board incompatibilities

**Target device:** X96 MAX+ **2101W**, Amlogic S905X3/SM1, 4 GiB RAM, 64 GiB eMMC, JL2101 Gigabit Ethernet, W522A (K255B-SR / W155S1) wireless. GitHub [ophub Armbian Issue #929](https://github.com/ophub/amlogic-s9xxx-armbian/issues/929) records this combination on PCB `Q5X3_141 V4.1 20112`. **Actual unit's PCB markings are not yet confirmed**, and the same silkscreen can accompany different peripheral configurations.

The 2024 [2101W original-style factory ROM](https://github.com/Grinch27/TWRP_x96maxplus2101w/releases/tag/firmware-2101w-stock-20240508-42466511950-1) was successfully downloaded and parsed into original and subpartition images. Its multi-DTB contains the **`sm1_ac213_4g` candidate**, with original Recovery Boot Header v1. This is evidence from the package, **not proof of the bootloader selection on this exact box**.

**Never replace it with** a `u212` (S905X2), `2101` (often RTL8822CS), `Plus2`, `Q1` or `Q2` recovery/firmware without independently proving matching flash layout, bootloader, DRAM init, DTB and peripherals. Shared S905X3 model names are insufficient.

## Four different image / recovery paths

| Medium | Image | What it does | Verified on this particular 2101W? |
| --- | --- | --- | --- |
| Windows **Amlogic USB Burning Tool** | Complete *Amlogic Upgrade Package* (e.g. archived 2024 `amlogic-factory-package.img`) | Reinstalls full Android firmware, potentially overwrites partition data and bootloader | **Not tested**; package static structure validated |
| Android bootloader/Recovery or dedicated partition tool | **Individual `recovery.img` Android Boot Image** generated by `make recoveryimage` | Tests/installs independent Recovery | **Not tested**; no validated compiled candidate yet |
| FAT32 microSD/USB root `recovery.img` and AV reset | Alternative *external Recovery loading* path reported for other X96 Max Plus models | Might temporarily start a Recovery without overwriting eMMC | **Not confirmed for 2101W**; needs bootloader capability check |
| UART / Amlogic mask-ROM / hardware test points | Rescue/boot diagnosis if firmware bootloader cannot enter Android | Last-resort board recovery | **Test-point location/polarity unknown**; no board shorting authorized |

A **single-partition `recovery.img` is not an Amlogic Upgrade Package** and **must not be imported directly into USB Burning Tool**. The Android factory ROM archive also is not a byte-for-byte full 64 GiB eMMC backup.

## Sources ranked by relevance

1. **Firsthand 2101W flashing narrative:** [Travis90x, X96 MAX+ S905X3 Armbian and stock recovery](https://travis90x.altervista.org/x96-max-plus-anlogic-s905x3-armbian/), published 2022-11-01. Author explicitly identifies a **2101W** and uses a **short USB-A-to-USB-A cable with the box's USB 3.0 port** to connect to Windows USB Burning Tool. After mistakenly flashing Plus2 stock, Bluetooth and Wi-Fi failed; the author reported a four-minute boot period and similarly prolonged AV-reset hold before USB Burning Tool could detect it. This is anecdotal and cannot be generalized to all revisions.
2. **Exact 4/64 hardware-revision report:** [ophub/amlogic-s9xxx-armbian #929](https://github.com/ophub/amlogic-s9xxx-armbian/issues/929) records a 2101W user, JL2101/W522A, and mentions an internal **recovery short pin**; no safe shorting diagram for our specific PCB is confirmed.
3. **OEM-style USB Burning Tool documentation:** [X96mini's USB Burning Tool guide](https://x96mini.com/blogs/news/how-to-use-amlogic-usb-burning-tool) describes using a complete image and warns that flashing **erases user data**. It lists **v2.1.7.0 for Android 9.0**; version compatibility should be confirmed with the actual supplied image and host.
4. **X96 Max Plus (not necessarily 2101W) USB flashing:** [Fan of Infinity](https://fanzz.cc/index.php/archives/362/) describes **USB 3.0**, USB-A-to-USB-A, Windows tool and no separate DC power in their instance. Other [X96 Max Plus rescue records](https://www.znds.com/tv-1191960-1-1.html) report similar, but **Q1 and other flash images must not be transplanted**.
5. **Alternative Recovery boot descriptions for other variants:** [ZNDS TWRP walkthrough](https://www.znds.com/tv-1172561-1-1.html) and [independent Max Plus 2 article](https://palmarci.me/blog/2025-04-27-installing-custom-fw-on-the-x96-max-plus-2-android-tv-box/index.html) report AV-port reset and external `recovery.img` loading. These do **not** establish 2101W support.
6. **Official TeamWin `u212` page:** [twrp.me/amlogic/amlogicu212.html](https://twrp.me/amlogic/amlogicu212.html) is for a distinct **S905X2/G12A** device and must not be treated as an official 2101W installer.
7. **Amlogic boot/image taxonomy:** [Geniatech S905X3 Android development specification](https://file.geniatech.com/thcdownloads/geniatech/resources/XPI-S905X3_Android_development%20specification_En_V1.0.pdf) distinguishes the upgrade package (`aml_upgrade_package.img`) from individual `recovery.img` and documents a U-Boot `usb_update/sdc_update recovery` method for its **different hardware**. This is architectural guidance, not a verified 2101W command.

## Non-writing preparation (no hardware access performed)

First obtain **actual-unit read-only evidence**, preferably while stock Android still boots:
- Hardware: PCB photo (both sides), eMMC and RAM markings, JL2101 PHY and W522A labels, USB 3.0 port identification and confirmation that the AV jack contains a reset switch.
- Software: `adb devices -l`; `adb shell getprop ro.product.device`; `adb shell getprop ro.board.platform`; `adb shell getprop ro.bootloader`; `adb shell cat /proc/partitions`; `adb shell cat /proc/mounts`; and, where permitted by Android permissions, read-only `/proc/device-tree/model`, `/proc/device-tree/compatible` and partition `by-name` mapping.
- Backup before attempting modifications: original Recovery, Boot, DTB, DTBO, vbmeta and **bootloader-specific partition layout**; ideally a complete eMMC backup with recovery proof. A public factory ROM is **not** a substitute for device-unique data.
- Host: Windows PC, suitable USB-A-to-USB-A data cable without improvised power adapters, verified Amlogic USB driver, stable power and a proven full *2101W* stock ROM fallback. Never connect two independent 5V supplies in an unverified electrical configuration.

If the original firmware is still bootable, **do not select Erase flash/Erase bootloader or start USB Burning Tool merely to confirm connection**. Windows USB device enumeration and recognized loader IDs are read-only diagnostic evidence; a write process is a separate approval gate.

## Staged test order and approval gates

1. **P0 OFFLINE (authorized):** actual TWRP 9 Native build; Android Boot Image v1, 2 KiB page, kernel/second/DTBO exact-byte checks; identify real recovery partition capacity (16 MiB is currently only a conservative provisional ceiling); ensure TWRP executable, init, fstab and USB input paths exist. Output short-lived GitHub Actions Artifact, **no Release**.
2. **P1 READ-ONLY DEVICE DISCOVERY — separate permission when hardware is available:** verify matching actual PCB, bootloader and partition map; confirm USB Host keyboard and mouse input paths from runtime logs; preserve full recovery/rollback evidence.
3. **P1 REVERSIBLE BOOT ATTEMPT — separate explicit approval:** **only if** the exact bootloader is demonstrated to accept external microSD/USB recovery or `fastboot boot`, use a non-writing boot attempt. Lack of proof means stop; an external `recovery.img` may be ignored or may invoke an updater on some vendor bootloaders.
4. **P2 WRITING A RECOVERY PARTITION — HIGH-risk explicit approval:** only after non-writing path is validated or evidence rules it out, actual recovery partition size checked, matching original partition backup completed, rollback proved. No default `fastboot flash recovery` assumption.
5. **P3 FULL FACTORY RESTORE — HIGH/CRITICAL-risk explicit approval:** use only exact-version complete **2101W** Amlogic package in USB Burning Tool after verifying its compatibility. *Erase bootloader* and whole-flash erasure are not standard troubleshooting toggles; they may destroy device-unique data or the only recovery loader. No arbitrary shorting of the PCB, eMMC pins or unknown test points.

### Stop conditions

Stop if any of: model/PCB revision mismatches, uncertain bootloader/Recovery partition size, invalid or oversized TWRP image, missing backup, unknown USB electrical configuration, unexpectedly different USB device ID, inability to restore factory Android, or any unexpected prompt involving `Erase flash` / `Erase bootloader` / writing persistent storage.

## Acceptance statuses

- **Confirmed:** 2024 full factory package archived; correct Android recovery boot layout and stock-derived binary inputs extracted in prior GitHub Actions; sources of a firsthand 2101W USB burn procedure identified.
- **Unknown:** native TWRP boot, actual-user-box U-Boot/DTB selection, USB mouse/keyboard functionality, HDMI display, TWRP storage mounts, bootloader unlock/fastboot support and 2101W-specific temporary external Recovery loading.
- **Not performed:** actual 2101W connection, flashing, bootloader unlocking, shorting, erase, Recovery partition writes or real hardware boot tests.
